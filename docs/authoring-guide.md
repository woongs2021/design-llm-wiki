# Authoring Guide

목표: 디자인 캡처 1건을 Obsidian에 아카이빙하고, 작업창의 LLM이 요청에 따라 분석과 wiki 갱신을 수행할 때 무엇을 쓰고, 무엇을 쓰지 않는지 정한다. 파일에서 계산 가능한 값은 Markdown에 쓰지 않는다.

참조 결정: `D-01`, `D-05`, `D-06`, `D-08`, `D-10`, `D-11`, `D-14`, `D-16`, `D-17`

## 작성 원칙

- 캡처 1건은 `obsidian/captures/<slug>/index.md` 한 파일에 저술한다.
- 원본 자산은 같은 폴더에 둔다.
- 이미지 분석은 자동화하지 않는다. 사용자가 작업창에서 요청할 때 LLM이 분석 초안을 쓰고, 사람은 보안·공개 가능 여부와 해석 방향을 검토한다.
- 치수, 파일 크기, 포맷, 프레임 수, 재생 시간, 해시는 쓰지 않는다. 빌드가 파일에서 파생한다.
- 확신할 수 없는 판단은 통과로 추정하지 않고 `사용자 확인 필요` 또는 `미확정`으로 남긴다.
- 관찰된 외부 제품의 색상 hex는 분석 데이터로 쓸 수 있다. 컴포넌트 스타일 토큰과 혼동하지 않는다.
- 의미 있는 분석, 비교, 질문 답변은 채팅에만 남기지 않고 `obsidian/wiki/`에 축적한다.

## 캡처 1건 작성 절차

| 순서 | 작업 | 검증 |
|---|---|---|
| 1 | `obsidian/captures/<slug>/` 폴더를 만든다. slug는 영문 소문자, 숫자, 하이픈만 사용한다. | 폴더명과 `index.md`의 slug가 같아야 한다. |
| 2 | 원본 캡처 파일을 같은 폴더에 넣는다. 스틸은 `PNG/JPG/WebP`, 모션은 `GIF/MP4/WebM`만 사용한다. | `asset` 경로가 같은 폴더 안의 실제 파일을 가리켜야 한다. |
| 3 | 템플릿을 복사해 frontmatter를 작성한다. | `npm run validate`가 필수 필드 누락 없이 통과해야 한다. |
| 4 | 작업창에서 LLM에게 `ingest`를 요청해 분석 초안을 작성하게 한다. 자동 watcher나 브라우저 이미지 분석 API를 쓰지 않는다. | 분석 항목 10개가 비어 있지 않아야 한다. 모호한 항목은 `미확정`과 이유를 쓴다. |
| 5 | public 공개 가능 여부를 판단해 `visibility`를 쓴다. 확신이 없으면 `internal`로 둔다. | public 빌드에서 해당 항목이 의도대로 포함 또는 제외되는지 빌드 리포트로 확인한다. |
| 6 | 태그를 통제 어휘에 맞춰 쓴다. 동의어는 빌드에서 정규화되지만, 새 태그가 필요하면 어휘 파일 추가 계획을 먼저 세운다. | `npm run validate`에서 미등록 태그가 실패해야 한다. |
| 7 | 관련 패턴, 서비스, 비교, 질문 페이지가 필요하면 `obsidian/wiki/`를 갱신한다. | `obsidian/wiki/index.md`에 새 페이지 링크가 있고, `obsidian/wiki/log.md`에 `ingest` 항목이 추가되어야 한다. |

## 분석 항목 기준

| 항목 | 작성 기준 | 쓰지 말아야 할 것 |
|---|---|---|
| 서비스/제품 | 캡처의 출처 서비스나 제품명을 쓴다. 사내 도구라면 내부 코드명보다 사용자가 이해하는 이름을 우선한다. | 파일명에서 추정한 서비스명을 확정값처럼 쓰지 않는다. |
| 플랫폼 | web, iOS, Android, desktop 등 실제 실행 환경을 쓴다. 반응형 웹의 모바일 뷰라면 web-mobile처럼 통제 어휘로 표현한다. | 화면 비율만 보고 플랫폼을 단정하지 않는다. |
| 화면 유형 | onboarding, dashboard, settings, checkout, empty-state처럼 화면의 목적을 쓴다. | UI 컴포넌트 이름만으로 화면 유형을 대신하지 않는다. |
| UI 패턴 | card-grid, split-view, command-palette, timeline처럼 재사용 가능한 인터페이스 패턴을 쓴다. | 모든 시각 요소를 태그로 과도하게 나열하지 않는다. |
| 레이아웃 구조 | 정보의 배치와 우선순위를 설명한다. 예: 좌측 필터, 우측 결과 그리드, 상단 요약 지표. | 픽셀 치수나 컬럼 수를 손으로 쓰지 않는다. 화면에서 명확히 보이는 구조만 쓴다. |
| 톤과 컬러 | 차분함, 경고성, 에디토리얼, 데이터 중심 등 인상과 컬러 역할을 함께 쓴다. 관찰된 hex는 데이터로 기록할 수 있다. | 사이트 컴포넌트 스타일에 쓸 토큰처럼 외부 hex를 재사용하지 않는다. |
| 타이포 | 글자 크기의 대비, 제목/본문 위계, 숫자 강조, 캡션 밀도처럼 관찰 가능한 위계를 쓴다. | 이미지에서 글꼴명을 확정하지 않는다. 글꼴이 확실하지 않으면 `추정`으로 적지 말고 `미확정`으로 둔다. |
| 카피 톤 | 명령형, 안내형, 친근함, 절제됨, 긴장감 등 문장의 태도를 쓴다. | 문구를 전부 베껴 쓰기보다 활용 가능한 특징을 요약한다. |
| 인터랙션 | 모션 캡처에서 보이는 전환, hover, 선택, 필터링, 스크롤 반응을 쓴다. 정지 캡처에서 보이지 않는 동작은 `확인 필요`로 남긴다. | 실제로 보지 않은 인터랙션을 일반적인 패턴으로 추정하지 않는다. |
| 한 줄 인사이트 | 나중에 검색 결과에서 바로 활용할 수 있는 배움 하나를 쓴다. | 단순 설명을 반복하지 않는다. 예: "상단 요약 숫자가 필터 결과의 신뢰감을 만든다." |
| 태그 | 검색과 컬렉션에 쓸 짧은 키워드만 쓴다. | 문장형 태그, 임시 감상 태그, 한 번만 쓸 가능성이 높은 태그를 남발하지 않는다. |

## 파생하지 않고 사람이 써야 하는 값

| 값 | 이유 |
|---|---|
| 출처 URL | 파일만으로 알 수 없다. |
| 촬영일 | 파일 수정 시간은 복사나 체크아웃으로 바뀐다. |
| 서비스/제품 버전 | 캡처 이미지에 명확히 보이지 않는 한 파일에서 알 수 없다. |
| 공개 가능 여부 | 보안과 권한 판단은 사람이 해야 한다. |
| 분석 본문 | 판단과 종합은 파일에서 계산할 수 없다. 작업창 LLM이 초안을 쓸 수 있지만, 자동 실행하지 않고 사용자가 요청하고 검토한다. |

## LLM Wiki Operations

| 작업 | 언제 사용 | 해야 할 일 | 검증 |
|---|---|---|---|
| `ingest` | 새 캡처를 추가했을 때 | 캡처 분석을 작성하고 관련 패턴, 서비스, 비교 페이지를 갱신한다. | `obsidian/wiki/log.md`에 `ingest` 항목이 추가되고, 새 캡처 slug가 관련 wiki 페이지에서 링크되어야 한다. |
| `query` | 특정 질문이나 비교를 남기고 싶을 때 | `obsidian/wiki/index.md`를 먼저 읽고 관련 페이지를 따라가 답을 만든다. 보존 가치가 있으면 `questions/` 또는 `comparisons/`에 파일로 남긴다. | 답변 파일이 참조한 캡처 slug와 wiki 페이지 링크를 포함해야 한다. |
| `lint` | wiki가 커진 뒤 정합성을 점검할 때 | 고아 페이지, 깨진 링크, 충돌 주장, 빠진 역링크, 미분류 페이지를 찾고 정리한다. | `log.md`에 `lint` 항목이 추가되고, 발견 수와 처리 수가 적혀야 한다. |

## 작성 후 확인

| 확인 | 실행 또는 관찰 | 기대 결과 |
|---|---|---|
| 스키마 검증 | `npm run validate` | 필수 필드, 통제 어휘, 자산 경로가 모두 통과한다. |
| internal 빌드 | `npm run build -- --target=internal` | 새 캡처가 포함되고 파생 메타가 리포트에 나타난다. |
| public 빌드 | `npm run build -- --target=public` | `visibility: public` 항목만 포함된다. internal 항목은 개수와 이유가 리포트에 표시된다. |
| 중복 확인 | 빌드 리포트 확인 | 같은 파일 해시가 있으면 경고 그룹이 보인다. |
| 용량 확인 | 빌드 리포트 확인 | 1GB 대비 잔여 용량과 100MB 초과 파일 목록이 보인다. |

## 미확정 표기

확인하지 못한 값을 추정하지 않는다. 아래처럼 이유를 함께 남긴다.

```md
interaction: 사용자 확인 필요 — 정지 캡처라 hover/transition 동작을 확인할 수 없음
typeface: 미확정 — 이미지에서 글꼴명을 확정할 수 없음
```
