# Phase 4 — Detail, Collections, Stats, Prompt Export

목표: 캡처를 검색한 뒤 실제로 활용하는 화면을 만든다. 상세, 컬렉션, LLM Wiki 페이지는 Obsidian 저술을 반영하고, 통계와 프롬프트 내보내기는 빌드된 JSON에서만 파생한다.

참조 결정: `D-01`, `D-05`, `D-08`, `D-09`, `D-10`, `D-14`, `D-16`, `D-17`

## 작업 계획

| 작업 | 계획 | 검증 |
|---|---|---|
| 상세 페이지 | 원본 뷰, 분석 전문, 파생 메타, 태그, 관련 캡처를 한 화면에 둔다. 모션은 poster와 controls를 함께 사용한다. | `#/capture/<slug>`로 직접 접근하면 해당 항목이 열려야 한다. 스틸은 원본 이미지가, 모션은 poster와 재생 컨트롤이 보여야 한다. |
| 파생 메타 표시 | 치수, 포맷, 바이트, 프레임 수, 재생 시간, 해시를 JSON에서 읽어 표시한다. Markdown에 같은 값을 쓰지 않는다. | 샘플 노트에 `width` 같은 필드를 추가하면 `npm run validate`가 실패해야 한다. 상세 표시 값은 빌드 JSON과 일치해야 한다. |
| 관련 캡처 | 태그와 UI 패턴의 교집합을 기준으로 관련 캡처를 계산한다. 규칙은 공유 모듈에 둔다. | 같은 입력 데이터에 대해 상세 페이지와 단위 테스트의 관련 캡처 slug 목록이 일치해야 한다. |
| 관련 wiki 페이지 | 상세 페이지에서 해당 캡처를 참조하는 패턴, 서비스, 비교, 질문 페이지를 보여준다. | 샘플 wiki 페이지에 캡처 slug를 링크하면 상세 페이지의 관련 wiki 섹션에 표시되어야 한다. |
| 컬렉션 | `obsidian/collections/*.md`를 사람이 저술한다. 컬렉션은 캡처 slug 목록과 설명을 갖고, 빌드는 참조 유효성을 검증한다. | 존재하지 않는 slug를 컬렉션에 넣으면 `npm run validate`가 파일 경로와 slug를 출력하고 실패해야 한다. |
| 컬렉션 화면 | 컬렉션 목록과 컬렉션 상세를 제공한다. 컬렉션 상세의 카드 순서는 Markdown에 사람이 쓴 순서를 따른다. | 컬렉션 Markdown의 slug 순서를 바꾸면 화면 순서도 바뀌어야 한다. |
| LLM Wiki 화면 | `obsidian/wiki/index.md`를 카탈로그로 보여주고, patterns/services/comparisons/questions 페이지를 읽기 전용으로 탐색한다. | `obsidian/wiki/index.md`에 있는 링크 수와 웹의 wiki 카탈로그 항목 수가 일치해야 한다. |
| 통계 화면 | 태그, 플랫폼, 화면 유형, UI 패턴, visibility 분포와 수집 추이를 표시한다. 차트는 격자와 그라디언트 없이 단색 면과 큰 숫자를 사용한다. | 화면의 합계가 `index.json` 전체 건수와 일치해야 한다. public 빌드에서는 internal 건수가 통계에 남지 않아야 한다. |
| 프롬프트 내보내기 | 선택한 캡처의 핵심 분석과 연결된 wiki 페이지 요약을 LLM 컨텍스트로 묶는다. `src/shared/promptExport.ts`의 한 함수가 미리보기 문자열과 클립보드 문자열을 모두 만든다. | 미리보기 DOM의 `textContent`와 클립보드에 복사된 문자열이 문자 단위로 동일해야 한다. |
| 선택 상태 | 갤러리와 상세에서 캡처를 선택 목록에 추가할 수 있다. 선택 목록은 브라우저 세션 안에서만 유지하고 서버 저장소를 만들지 않는다. | 새로고침 후 선택 상태 처리 방식이 문서화된 동작과 일치해야 한다. 서버 요청이나 외부 저장소 요청이 없어야 한다. |

## 프롬프트 내보내기 형식 원칙

- 캡처별 제목, 서비스, 플랫폼, 화면 유형, UI 패턴, 한 줄 인사이트를 포함한다.
- 연결된 wiki 페이지가 있으면 페이지 제목, 한 줄 요약, 링크를 포함한다.
- 긴 분석 본문은 선택된 항목만 포함한다.
- internal/public 빌드 경계를 넘지 않는다. public 번들에서는 internal 캡처가 선택 후보에 없어야 한다.
- 미리보기와 실제 복사 문자열은 같은 함수 결과를 사용한다.

## LLM Wiki 활용 원칙

- 웹은 wiki를 편집하지 않는다. 편집은 사용자가 작업창에서 `ingest`, `query`, `lint`를 요청할 때만 일어난다.
- 사용자가 웹에서 얻은 질문이나 비교 결과를 보존하고 싶으면, 작업창에서 query 결과를 `obsidian/wiki/questions/` 또는 `obsidian/wiki/comparisons/`에 파일로 남긴다.
- `obsidian/wiki/log.md`는 웹에 읽기 전용으로 보여줄 수 있지만, 브라우저에서 갱신하지 않는다.

## 통계 표시 원칙

- 디자인 시스템의 "큰 숫자 + 단색 면" 원칙을 따른다.
- 색상 hex를 직접 쓰지 않고 토큰만 참조한다.
- 수치를 문서에 고정해 적지 않는다. 화면은 JSON에서 계산한다.

## 통과 기준

- 상세와 컬렉션은 빌드 JSON에 존재하는 항목만 보여준다.
- LLM Wiki 카탈로그와 페이지는 빌드 JSON에 존재하는 wiki 항목만 보여준다.
- 컬렉션 참조 무결성은 빌드에서 실패로 막는다.
- 통계 합계가 현재 데이터와 일치한다.
- 프롬프트 미리보기와 복사 산출물이 다르지 않다.
